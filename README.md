# ZUCA Ops

ZUCA багийн дотоод удирдлагын вэб: ажил (task), зуслангийн жагсаалт, тайлан.

**Stack:** Next.js 16 (App Router) · React 19 · Tailwind CSS 4 · Supabase (Postgres, Auth, Realtime) · dnd-kit

## Юу хийдэг вэ

| Хуудас | Боломж |
|---|---|
| **Самбар** `/` | Миний ажил, яаралтай, хугацаа хэтэрсэн, мэдээлэл дутуу зуслангийн тоо. Анхаарах ажлууд, хамгийн дутуу мэдээлэлтэй зуслангууд, 7 хоногийн график |
| **Ажлууд** `/tasks` | Kanban самбар, чирж зөөнө. **Төлөвөөр** (Хийх → Хийж байна → Шалгах → Дууссан) эсвэл **Яаралтай байдлаар** (Яаралтай / Өндөр / Дунд / Бага) харна. Хүн, яаралтай байдал, хугацаа хэтэрснээр шүүнэ. `N` товч = шинэ ажил |
| **Төлөвлөгөө** `/plan` | Ажлаа **жил / улирал / сар**-аар төлөвлөнө. Жил, улирлын харагдацад сар бүр нэг багана — ажлыг сар хооронд чирж зөөнө, «Төлөвлөөгүй» баганаас сар руу чирж төлөвлөнө. Сарын харагдац нь тухайн сарын ажлуудыг төлөвөөр харуулна (Ажлууд хуудсанд «сар» шүүлтүүрээр мөн харагдана). **Тайлан** таб: сар, улирал, жилийн гүйцэтгэл % (төлөвлөсөн/дууссан/хэтэрсэн), хүн тус бүр, сарын ажлын жагсаалт, CSV, хэвлэх |
| **Зуслангууд** `/camps` | Монголын бүх зуслан. **Pipeline** (Холбогдоогүй → Холбогдсон → Бүртгэж байна → Идэвхтэй → Идэвхгүй) чирж зөөнө, эсвэл **Хүснэгт**. Зуслан бүрт мэдээллийн бүрэн байдлын % ба дутуу талбарууд. "Нөхөх ажил үүсгэх" товч. CSV импорт/экспорт |
| **Ажилчид** `/team` | Багийн хүмүүсийг бүртгэнэ (нэр, албан тушаал, утас, имэйл, өнгө, эрх). Хэн хэдэн ажил хийж байгаа, хэд нь хугацаа хэтэрсэн, хэдэн зуслан хариуцаж байгааг нэг хүснэгтээс харна. Тоон дээр дарж тухайн хүний ажлууд руу шилжинэ. **Нэвтрэх эрхгүйгээр ажил хариуцуулж болно** |
| **Тайлан** `/reports` | 7/30/90 хоног: дууссан/шинэ ажил, гүйцэтгэх хугацаа, хугацаандаа дууссан %, гишүүн тус бүр, pipeline, дутуу мэдээлэл, аймгаар. CSV, хэвлэх |

Бүрэн байдлыг `src/lib/completeness.ts`-д тохируулна (утас, хүн, имэйл, аймаг, хаяг, координат, нас, багтаамж, үнэ, тайлбар, 3+ зураг, гэрээ).

## Эхлүүлэх

```bash
cd ~/Desktop/zuca-ops
npm install
npm run dev
```
→ http://localhost:3000

`.env.local` хоосон бол апп **Demo горим**-оор ажиллана (өгөгдөл browser-т хадгалагдана). Supabase-г холбохдоо:

### Supabase тохиргоо (нэг удаа)

1. **SQL Editor** → `supabase/schema.sql`-ийг бүтнээр нь paste хийгээд **Run**. (Дахин ажиллуулахад аюулгүй, өгөгдөл устахгүй.)
2. **SQL Editor** → `supabase/seed-zuca.sql` — **zuca.mn дээрх жинхэнэ 15 зуслан** + дутуу мэдээллийг нөхөх 11 ажил. Дахин ажиллуулахад давхардахгүй (`zuca_slug`-аар таньдаг), zuca.mn шинэчлэгдвэл дахин ажиллуулж мэдээллээ шинэчилнэ.
3. **SQL Editor** → `supabase/seed.sql` — **МҮЗХ-ны жагсаалтын бодит 73 зуслан** (2026.05.28). zuca.mn дээрх 15-тай `zuca_slug`-аар нийлж, өмчийн хэлбэр, регистр, байгуулагдсан он, хүчин чадлыг нь нэмнэ. Үлдсэн 58 нь «Холбогдоогүй» (5 нь «Идэвхгүй») төлөвтэй орно. Өмнөх хувилбарын зохиомол жишээ зуслангуудыг цэвэрлэнэ. Дахин ажиллуулахад давхардахгүй.
4. **Authentication → Sign In / Providers → Email**: дотоод хэрэгсэл тул "Confirm email"-ийг унтраавал бүртгүүлмэгц шууд нэвтэрнэ. Асаалттай бол баталгаажуулах имэйл очно.
5. `.env.local`:
   ```
   NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
   ```
6. `npm run dev` → **Бүртгүүлэх** табаар нэвтэрнэ.
7. **Ажилчид** хуудсаар багийнхаа хүмүүсийг бүртгэнэ. Имэйлийг нь зөв оруулбал тэр хүн дараа нь **ижил имэйлээр** бүртгүүлэхэд энэ мөртэй автоматаар холбогдож, өөрийн ажлаа хардаг болно.

> Database password, `service_role` / secret key-г **хэзээ ч** кодод, `.env.local`-д бүү тавь — энэ апп зөвхөн publishable key ашиглана. Хамгаалалтыг RLS (Row Level Security) хийдэг: зөвхөн нэвтэрсэн хэрэглэгч өгөгдөл харна.

Анхаар: Supabase-д бүртгэлийг хэн ч нээж болно. Зөвхөн багийнхаа хүмүүсийг оруулахын тулд бүгд бүртгүүлсний дараа **Authentication → Sign In / Providers → "Allow new users to sign up"**-ийг унтраа.

## Бодит өгөгдөл ба ангилал

| Талбар | Утга |
|---|---|
| **Төлөв** | zuca.mn дээр байгаа 15 → «ZUCA дээр идэвхтэй»; тайлбарт «ажиллаагүй / зарагдсан / нураасан» гэсэн 5 → «Идэвхгүй»; бусад 53 → «Холбогдоогүй» |
| **Өмчийн хэлбэр** | Хувийн 37 · Орон нутгийн 14 · Хөдөлмөр зуслан 9 · Төрийн 6 · Байгууллагын дэргэд 2 · Тодорхойгүй 5 |
| Бусад | Регистрийн дугаар, байгуулагдсан он, суурин газраас зай, хүчин чадал, МҮЗХ-ны тайлбар (Тэмдэглэл-д) |

Excel шинэчлэгдвэл:
```bash
python3 scripts/import_mn_camps.py "МҮЗХолбоо зуслангийн жагсаалт.xlsx"   # → src/lib/camps-mn.json
python3 scripts/gen_seed.py > supabase/seed.sql
```
zuca.mn дээрх зуслангуудын жагсаалт `scripts/import_mn_camps.py`-ийн `ZUCA` хэсэгт байна.

## Ажилчид ба ажил хариуцуулах

`profiles` хүснэгт нь **auth-аас хараат бус**. Тиймээс:

- Менежер ажилтныг урьдчилан бүртгээд **шууд ажил хариуцуулж болно** — тэр хүн нэвтрэх шаардлагагүй.
- Тухайн хүн хожим **ижил имэйлээр** бүртгүүлэхэд `handle_new_user` trigger нь `user_id`-г нь холбож өгнө. Шинэ мөр үүсэхгүй, хариуцаж байсан ажлууд нь хэвээр үлдэнэ.
- Ажлаас гарсан хүнийг **устгахын оронд «Идэвхгүй»** болго — түүхэн тайлан бүрэн үлдэнэ. Устгавал ажил, зуслан нь устахгүй, зөвхөн хариуцагчгүй болно.
- Зуслан бүрт `owner_id` (ZUCA-гаас хариуцагч) тавина — зуслангийн карт дотроос сонгоно.

## Бүтэц

```
src/
  app/(app)/          самбар, tasks, camps, team, reports
  app/login/          нэвтрэх / бүртгүүлэх
  components/board.tsx  дахин ашиглах drag-and-drop Kanban
  lib/data/           store (optimistic UI), supabase-repo, demo-repo
  lib/completeness.ts мэдээллийн бүрэн байдлын дүрэм
  proxy.ts            session шинэчлэх, нэвтрээгүйг /login руу
supabase/
  schema.sql          хүснэгт, enum, trigger, RLS, realtime
  seed-zuca.sql       zuca.mn-ий жинхэнэ 15 зуслан + нөхөх ажлууд
  seed.sql            МҮЗХ-ны бодит 73 зуслан (seed-zuca-ийн дараа)
scripts/
  import_mn_camps.py  Excel + zuca.mn → src/lib/camps-mn.json
  gen_seed.py         camps-mn.json → supabase/seed.sql
```

## Deploy (Vercel)
