# ZUCA Ops

**Зөвхөн ZUCA-д** зориулсан дотоод систем: ажил, чат + AI, зуслангийн CRM, zuca.mn-ийн өдөр тутмын синк, тайлан — шинэ ажил оноогдмогц Telegram-аар мэдэгдэж, өглөө бүр хүн бүрт өнөөдрийн ажлыг нь цэгцэлж илгээдэг **AI туслах**. Дизайн: bento, liquid glass, light/dark (системийг дагана), хажуугийн цэс.

**Stack:** Next.js 16 (App Router) · React 19 · Tailwind CSS 4 · Supabase (Postgres, Auth, Realtime, RLS) · Claude API (`claude-opus-5-5`) · nodemailer (SMTP) · Telegram Bot API · Vercel Cron · dnd-kit

## Юу хийдэг вэ

| Хуудас | Боломж |
|---|---|
| **AI туслах** `/agent` | Claude өнөөдрийн ажлыг дараалал, цагийн хуваарьтай цэгцэлж, **нэг товшилтоор хэрэгжүүлэх санал** (ач холбогдол, хугацаа, шилжүүлэх, хаах) гаргана. Имэйл, Telegram мессежийг урьдчилан харж, өөртөө / хэлтэстээ / бүгдэд одоо илгээнэ. Telegram холбох, мэдэгдлийн тохиргоо, илгээлтийн түүх |
| **Чат** `/chat` | **Slack шиг багийн чат + AI.** Сувагт «Бат, маргааш Хөх тэнгэрт залгаарай» гэж бичихэд AI ажлыг Батад, маргаашийн хугацаатай **автоматаар** үүсгэж, картаар харуулна (↶ товчоор буцаана). `@ai` гэж асуулт асууна, ажил хуваарилуулна, төлөв өөрчилнө. Мессеж бүр дээр «✨ Ажил болгох». Суваг бүрийн AI горим: Автомат / Санал болгох / Зөвхөн @ai / Унтраах. **«Ирсэн хүсэлт»** суваг — имэйл, zuca.mn, Facebook-ээс автоматаар орж ирсэн мессеж |
| **Самбар** `/` | Bento самбар: миний нээлттэй ажил, 7 хоногийн гүйцэтгэл, хэтэрсэн, ажлын урсгал (pill график), нээлттэй ажлын бүтэц (donut), zuca.mn-ийн шууд мэдээлэл (удахгүй эхлэх ээлж, дүүргэлт %), AI туслах, мэдээлэл дутуу зуслан |
| **Ажлууд** `/tasks` | **Админ** бүх ажилтны ажил, хүн бүрийн гүйцэтгэл %-ийг («Ажилчдын явц») харна. **Ажилтан** зөвхөн өөрийн болон эзэнгүй ажлаа харж, эзэнгүй ажлыг «Би авъя» гэж авна. Kanban самбар, чирж зөөнө. **Төлөвөөр** (Хийх → Хийж байна → Шалгах → Дууссан) эсвэл **Яаралтай байдлаар** (Яаралтай / Өндөр / Дунд / Бага) харна. Хүн, яаралтай байдал, хугацаа хэтэрснээр шүүнэ. `N` товч = шинэ ажил |
| **Төлөвлөгөө** `/plan` | Ажлаа **жил / улирал / сар**-аар төлөвлөнө. Жил, улирлын харагдацад сар бүр нэг багана — ажлыг сар хооронд чирж зөөнө, «Төлөвлөөгүй» баганаас сар руу чирж төлөвлөнө. Сарын харагдац нь тухайн сарын ажлуудыг төлөвөөр харуулна (Ажлууд хуудсанд «сар» шүүлтүүрээр мөн харагдана). **Тайлан** таб: сар, улирал, жилийн гүйцэтгэл % (төлөвлөсөн/дууссан/хэтэрсэн), хүн тус бүр, сарын ажлын жагсаалт, CSV, хэвлэх |
| **Зуслангууд** `/camps` | **zuca.mn-ээс орой бүр 21:00-д** зуслан, ээлж, үнэлгээ, сэтгэгдэл, байршлыг автоматаар татаж шинэчилнэ («Одоо шинэчлэх» товч). Монголын бүх зуслан. **Pipeline** (Холбогдоогүй → Холбогдсон → Бүртгэж байна → Идэвхтэй → Идэвхгүй) чирж зөөнө, эсвэл **Хүснэгт**. Зуслан бүрт мэдээллийн бүрэн байдлын % ба дутуу талбарууд. "Нөхөх ажил үүсгэх" товч. CSV импорт/экспорт |
| **Баг** `/team` (админ) | Ажилтан бүрийн карт: эрх, хэлтэс, нээлттэй/хэтэрсэн/дууссан, 30 хоногийн гүйцэтгэл %, Telegram холбогдсон эсэх. «Хэлтэс» товчоор хэлтэс засна (AI ажлыг хэлтэст нь хуваарилахад хэрэглэнэ). Багийн хүмүүсийг бүртгэнэ (нэр, албан тушаал, утас, имэйл, өнгө, эрх). Хэн хэдэн ажил хийж байгаа, хэд нь хугацаа хэтэрсэн, хэдэн зуслан хариуцаж байгааг нэг хүснэгтээс харна. Тоон дээр дарж тухайн хүний ажлууд руу шилжинэ. **Нэвтрэх эрхгүйгээр ажил хариуцуулж болно** |
| **Тайлан** `/reports` (админ) | 7/30/90 хоног: **хэлтэс бүрийн гүйцэтгэл** (хугацаандаа %, ирсэн хүсэлт), дууссан/шинэ ажил, гүйцэтгэх хугацаа, хугацаандаа дууссан %, гишүүн тус бүр, pipeline, дутуу мэдээлэл, аймгаар. CSV, хэвлэх |

Бүрэн байдлыг `src/lib/completeness.ts`-д тохируулна (утас, хүн, имэйл, аймаг, хаяг, координат, нас, багтаамж, үнэ, тайлбар, 3+ зураг, гэрээ).

## Эхлүүлэх

```bash
cd ~/Desktop/zuca-ops
npm install
npm run dev
```
→ http://localhost:3000

`.env.local` хоосон бол апп **Demo горим**-оор ажиллана (өгөгдөл browser-т хадгалагдана). Supabase-г холбохдоо:

### Supabase тохиргоо (нэг удаа)

1. **SQL Editor** → `supabase/schema.sql`-ийг бүтнээр нь paste хийгээд **Run**. (Дахин ажиллуулахад аюулгүй, өгөгдөл устахгүй.)
2. **SQL Editor** → `supabase/seed-zuca.sql` — **zuca.mn дээрх жинхэнэ 15 зуслан** + дутуу мэдээллийг нөхөх 11 ажил. Дахин ажиллуулахад давхардахгүй (`zuca_slug`-аар таньдаг), zuca.mn шинэчлэгдвэл дахин ажиллуулж мэдээллээ шинэчилнэ.
3. **SQL Editor** → `supabase/seed.sql` — **МҮЗХ-ны жагсаалтын бодит 73 зуслан** (2026.05.28). zuca.mn дээрх 15-тай `zuca_slug`-аар нийлж, өмчийн хэлбэр, регистр, байгуулагдсан он, хүчин чадлыг нь нэмнэ. Үлдсэн 58 нь «Холбогдоогүй» (5 нь «Идэвхгүй») төлөвтэй орно. Өмнөх хувилбарын зохиомол жишээ зуслангуудыг цэвэрлэнэ. Дахин ажиллуулахад давхардахгүй.
4. **Authentication → Sign In / Providers → Email**: дотоод хэрэгсэл тул "Confirm email"-ийг унтраавал бүртгүүлмэгц шууд нэвтэрнэ. Асаалттай бол баталгаажуулах имэйл очно.
5. `.env.local`:
   ```
   NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
   ```
6. `npm run dev` → **Бүртгүүлэх** табаар нэвтэрнэ.
7. **Ажилчид** хуудсаар багийнхаа хүмүүсийг бүртгэнэ. Имэйлийг нь зөв оруулбал тэр хүн дараа нь **ижил имэйлээр** бүртгүүлэхэд энэ мөртэй автоматаар холбогдож, өөрийн ажлаа хардаг болно.

> Browser зөвхөн publishable key ашиглана. `SUPABASE_SERVICE_ROLE_KEY`-г **зөвхөн** server-ийн env-д (`NEXT_PUBLIC_` угтваргүй) тавина — өглөөний cron болон Telegram bot л ашигладаг. Кодод, git-д хэзээ ч бүү оруул. Хамгаалалтыг RLS хийдэг (доорх «Эрх»).

Анхаар: Supabase-д бүртгэлийг хэн ч нээж болно. Зөвхөн багийнхаа хүмүүсийг оруулахын тулд бүгд бүртгүүлсний дараа **Authentication → Sign In / Providers → "Allow new users to sign up"**-ийг унтраа.

## Эрх (role)

ZUCA-д **хоёр эрх**:

| Эрх | Юу харах вэ |
|---|---|
| **Админ** | Бүх ажилтны ажил, хүн бүрийн явц %, Баг, Тайлан, тохиргоо, zuca.mn синк, эрх олгох |
| **Ажилтан** | Зөвхөн өөрт оноогдсон, өөрийн үүсгэсэн болон **эзэнгүй** ажил. Эзэнгүй ажлыг «Би авъя» гэж авна |

Дүрэм `src/lib/permissions.ts` (UI) болон `supabase/schema.sql` v6 (RLS) хоёрт давхар хэрэгжсэн. v6-г ажиллуулахад хуучин «Удирдлага» → Админ, «Хэлтсийн дарга» → Ажилтан болно. Анхны админыг Supabase SQL Editor-оор тавина: `update profiles set role = 'admin' where email = 'та@zuca.mn';`

## zuca.mn → ZUCA Ops (орой бүр)

```
21:00 (Улаанбаатар) ─ Vercel Cron ─► /api/cron/zuca
   └─ GET https://zuca.mn/api/v1/Camps/all + /Camps/detailed/{id}
        ├─ camps: аймаг, сум, хаяг, утас, имэйл, вэб, нас, багтаамж, үнэ, координат, үнэлгээ, сэтгэгдэл
        ├─ zuca_shifts: ээлж бүр (эхлэх/дуусах, багтаамж, бүртгэл, үнэ, өдрийн эсэх)
        ├─ шинэ зуслан → Партнершипийн даргад «шалгах» ажил + Telegram (анхны синкэд үүсгэхгүй)
        └─ #Ерөнхий сувагт товчоо: 14 хоногийн дүүргэлт, дүүргэлт сул ээлжүүд
```

Гараар: **Зуслангууд → «Одоо шинэчлэх»** эсвэл `curl -H "Authorization: Bearer $CRON_SECRET" "$APP_URL/api/cron/zuca"`. API хаягийг `ZUCA_API_URL`-ээр сольж болно (заавал биш).

## AI туслах, имэйл, Telegram

```
07:00 (Улаанбаатар) ─ Vercel Cron ─► /api/cron/daily
   └─ ажилтан бүрт: нээлттэй ажил
        ├─ Claude (claude-opus-5-5, structured output) → дараалал, цагийн хуваарь, санал, эрсдэл
        ├─ имэйл (SMTP)          ← notify_email
        └─ Telegram (Bot API)    ← notify_telegram + chat id
   └─ админд нэмж: хэлтэс бүрийн нээлттэй / хэтэрсэн ажил
```

1. `.env.local` (Vercel дээр Environment Variables)-д `.env.example`-ийн «AI туслах» хэсгийг бөглө. Аль нэг нь хоосон бол тэр суваг л унтарна — **AI туслах** хуудасны дээд мөрөнд юу тохирсныг харуулна.
2. **Telegram:** @BotFather → `/newbot` → token, username-ийг env-д. Deploy хийсний дараа админ **AI туслах → «Webhook тохируулах»** дарна. Ажилтан бүр **«Telegram холбох»** → bot дээр Start. Bot командууд: `/today`, `/plan` (AI), `/id`. **Шинэ ажил оноогдмогц** тухайн хүнд «▶️ Эхлүүлэх / ✅ Дууссан» товчтой мессеж очно (v6-д webhook-ийг дахин тохируулна).
3. **Cron:** `vercel.json`-д `0 23 * * *` (UTC) = 07:00. Vercel `CRON_SECRET`-ийг автоматаар Authorization header-т хийнэ. Гараар турших: `curl -H "Authorization: Bearer $CRON_SECRET" "$APP_URL/api/cron/daily?force=1"`. Амралтын өдөр алгасна (`DIGEST_WEEKENDS=1` бол илгээнэ).
4. AI-д зөвхөн ажлын гарчиг/тайлбар, хэлтсийн нэр очно — утас, имэйл очихгүй. Claude татгалзвал (refusal) server талд өөр model-оор автоматаар дахин оролдоно (`fallbacks: "default"`); AI унасан ч энгийн жагсаалт илгээгдэнэ.

## Чат + ажлыг автоматаар барих (v5)

Зорилго: ажлыг хэн ч гараар оруулахгүй — ажил хаана гарсан ч ZUCA Ops-д өөрөө орно.

```
Ажил гарах газар                       ZUCA AI (Claude, tool use)              Үр дүн
#Ерөнхий, хэлтсийн сувгууд ─────┐     search_tasks → давхардал шалгана       ┌─► tasks (tags: AI, source: chat)
Telegram bot-д энгийн текст ────┼───► create_task → хүн, хугацаа, зуслан ───┼─► чатад ажлын карт (↶ буцаах)
/api/intake (имэйл, zuca.mn) ───┤     update_task → дууссан, шилжүүлэх      └─► Telegram хариу
Өглөөний cron ──────────────────┘     (cron: дутуу мэдээлэлтэй зуслан → ажил, 3+ хоног хэтэрсэн → #Ерөнхий-д сануулга)
```

1. **Схем:** Supabase → SQL Editor → `supabase/schema.sql`-ийг дахин бүтнээр нь Run (v5 нэмэгдэнэ: `channels`, `messages`, `tasks.source`). Анхны сувгууд: #Ерөнхий, Ирсэн хүсэлт, хэлтэс бүрийн суваг.
2. **Env:** `ANTHROPIC_API_KEY` (заавал), `SUPABASE_SERVICE_ROLE_KEY` (intake, Telegram, cron), `INTAKE_SECRET` (гадаад эх үүсвэр).
3. **Чат** `/chat`: мессеж илгээхэд `/api/chat/send` хадгалаад хариугаа шууд буцаана; AI `after()` дотор ажиллаж хариу нь Realtime-аар ирнэ. Энгийн мессежийг `effort: low`, `@ai`-г `medium`-аар боловсруулна. «за», «ок» зэрэг 12 тэмдэгтээс богино мессежийг алгасна.
4. **Telegram:** холбогдсон хүн bot руу команд биш энгийн текст бичвэл AI ажлыг бүртгээд хариулна.
5. **Гадаад эх үүсвэр** `POST /api/intake` (`Authorization: Bearer $INTAKE_SECRET` эсвэл `?key=`):
   ```bash
   curl -X POST "$APP_URL/api/intake" -H "Authorization: Bearer $INTAKE_SECRET" -H "Content-Type: application/json" \
     -d '{"from":"Сараа (эцэг эх)","text":"Төлбөр 2 удаа гарсан, буцааж өгнө үү","ref":"gmail-123"}'
   ```
   `ref` давтагдвал дахин орохгүй. `zuca_camp_id` (zuca.mn-ийн зуслангийн ID → `camps.zuca_id`) эсвэл `camp` (нэр) өгвөл AI ажлыг тэр зуслантай холбоно. **zuca.mn** өөрөө `lib/zuca-ops.ts`-ээр холбоо барих форм, 1–3 одтой үнэлгээ, сургуулийн өдрийн захиалга, захиалгын backend-ийн алдааг энд илгээдэг (`ZUCA_OPS_INTAKE_URL`, `ZUCA_OPS_INTAKE_KEY`). Анхаар: intake мессеж (эцэг эхийн нэр, утас, имэйл орно) ажил болгохын тулд Claude-д очно. Supabase Database Webhook-ийн формат (`{type, table, record}`)-ыг шууд таньдаг — zuca.mn-ийн Supabase → Database → Webhooks → `…/api/intake?key=…&source=zuca.mn`. Gmail-ийн Apps Script, бусад заавар чатын «Ирсэн хүсэлт» → **Эх үүсвэр холбох** дотор бий.
6. **Өглөөний cron** (`/api/cron/daily`) өдрийн товчооны дараа: ZUCA-тай ажиллаж буй (холбогдсон / бүртгэж байна / идэвхтэй) зуслангийн дутуу мэдээлэлд «нөхөх» ажил үүсгэнэ (өдөрт ≤10, давхардуулахгүй, хариуцагч = зуслангийн owner), #Ерөнхий-д өглөөний товчоо + 3+ хоног хэтэрсэн ажлын жагсаалт бичнэ.

Эрх: мессежийг баг бүхэлдээ харна; хүн зөвхөн өөрийн нэрээр бичнэ (RLS). AI-ийн хариу түүнийг дуудсан хүний session-ээр бичигдэх тул AI тэр хүний эрхээс илүүг хийж чадахгүй. Сувгийн AI горимыг үүсгэгч, хэлтсийн дарга, удирдлага өөрчилнө.

Demo горимд (Supabase-гүй) AI цэгцлэлт, гараар илгээх нь локал орчинд ажиллана; cron болон bot-ын холболт Supabase шаардана.

## Ажилчид ба ажил хариуцуулах

`profiles` хүснэгт нь **auth-аас хараат бус**. Тиймээс:

- Менежер ажилтныг урьдчилан бүртгээд **шууд ажил хариуцуулж болно** — тэр хүн нэвтрэх шаардлагагүй.
- Тухайн хүн хожим **ижил имэйлээр** бүртгүүлэхэд `handle_new_user` trigger нь `user_id`-г нь холбож өгнө. Шинэ мөр үүсэхгүй, хариуцаж байсан ажлууд нь хэвээр үлдэнэ.
- Ажлаас гарсан хүнийг **устгахын оронд «Идэвхгүй»** болго — түүхэн тайлан бүрэн үлдэнэ. Устгавал ажил, зуслан нь устахгүй, зөвхөн хариуцагчгүй болно.
- Зуслан бүрт `owner_id` (ZUCA-гаас хариуцагч) тавина — зуслангийн карт дотроос сонгоно.
